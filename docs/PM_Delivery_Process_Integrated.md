# 통합 서비스 딜리버리 프로세스 (PM AI Workflow 기준안 v0.1)

작성: 2026-11-22 · 용도: PM AI 자동화 포트폴리오의 기준 프로세스
기준(A안): 본인이 수행한 PM 표준 딜리버리 프로세스 + Databricks 공개 딜리버리 모델(공동 OKR, 마이그레이션 5단계)

## 0. 출처와 원칙

| 구분 | 출처 | 반영 방식 |
|---|---|---|
| 서비스 딜리버리 흐름 | 일반적인 서비스 딜리버리 흐름(12단계) | 수주→인수인계→설치·인수→운영 이관의 실행 흐름 |
| PM 방법론 | 본인이 수행한 PM 표준 딜리버리 프로세스 | 5단계, Core Template, Project Workbook, Quality Health Check |
| 마이그레이션 SOW | 데이터 이관 프로젝트 SOW 사례(일반화) | 단계별 산출물, 진척 가중치, 보고·검토 주기, 인수 조건 |
| Databricks 공개 모델 | PS 공식 블로그·서비스 설명서 | 공동 OKR(P0/P1/P2), 마이그레이션 5단계, Pod 팀 |

원칙
- 외부 공개용이므로 사내 명칭, 고객명, 금액, 장비 사양은 쓰지 않는다.
- Databricks 내부 방법론이 아니라 "공개 모델에 맞춘 PM 표준 프로세스"로 표기한다.
- 하드웨어 설치 전용 단계(설치환경요구서, 케이블링, 장비 납품·대금 청구)는 데이터 플랫폼 PS에 맞지 않아 뺐다. 작업계획서·인수시험 개념은 "작업 단위 계획·검증"으로 일반화해 남겼다.

## 1. 단계 매핑 한눈에 보기

| 통합 단계 | 본인 PM 방법론 | 서비스 딜리버리 흐름 | 마이그레이션 SOW | Databricks 공개 모델 |
|---|---|---|---|---|
| P0 수주·인수인계 | Pre-Sales | ①~④ 제안·발주·PM 선임·제안 내역 전달 | — | Discovery·Assessment, SOW 확정 |
| P1 착수 | Initiate | ⑤ 팀 구성·예산 검토 | 프로젝트 준비 | 공동 OKR 정의, 우선순위(P0/P1/P2) |
| P2 계획 | Plan | ⑥~⑦ 수행 협의·작업계획서 | 현황분석 + 시스템 설계 | Strategy & Design |
| P3 수행·통제 | Execute | ⑧ 작업 반복 수행 | 구축·데이터 마이그레이션 | Production Pilot → Execution |
| P4 인수·이관 | Execute 후반 | ⑨~⑪ 인수시험서·인수시험·교육·자료 전달 | 안정화, 인수 조건 | Enablement, CoE |
| P5 종료 | Close | ⑫ 완료 보고·운영 이관 | 프로젝트 종료 | 회고, 후속 OKR |

## 2. 단계별 상세

### P0 수주·인수인계 (Sales → Delivery Handover)
- 목적: 판매된 범위를 딜리버리 팀이 정확히 넘겨받는다.
- 활동: 공수 산정 근거·서비스 예산 검토, SOW 검토, 영업·프리세일즈 Handover 미팅, 고객 환경·제안 유의사항 확인, PM 선임.
- 입력: 제안서, SOW·WBS 초안, 고객 환경 정보, 계약 조건.
- 산출물: Handover 체크리스트, 초기 리스크 목록.
- 게이트 G0: Handover 완료(체크 이벤트 1).
- AI 자동화 후보: SOW·제안서에서 범위·가정·제외 범위·리스크 자동 추출 → Handover 체크리스트 초안.

### P1 착수 (Initiate)
- 목적: 범위와 성공 기준을 고객과 같은 말로 확정한다.
- 활동: Project Charter 작성, Project Workbook 생성(Baseline), 고객 OKR 공동 검토와 우선순위 지정, 팀 구성.
- 산출물: Charter, 공동 OKR 표(목표·핵심 결과·성공 지표·의존성·목표 일정), Workbook.
- 게이트 G1: 범위·OKR 고객 합의.
- AI 자동화 후보: Charter·OKR 표 초안 생성, Workbook 초기화(Actions·Risks·Issues·Changes·Assumptions·WBS·Requirements).

### P2 계획 (Plan)
- 목적: 현황을 분석하고 이관·구축 계획과 검증 기준을 세운다.
- 활동: 현황 조사(이관 대상 정의, 환경·의존성·성능 분석), 위험요소 분석과 대응 방안, 이관 방식·도구 선정, 웨이브 계획(서비스 영향도에 따른 중단/무중단 구분), 테스트·검증 계획, 상세 일정, 범위 상호 인지 후 Customer Kickoff.
- 산출물: 현황조사 결과서, 이관(마이그레이션) 계획서, 테스트·검증 계획서, Detailed Project Plan, Kickoff 자료.
- 게이트 G2: 범위 합의 후 Kickoff 수행(체크 이벤트 2), 계획서 고객 승인.
- AI 자동화 후보: 회의 메모 → 회의록·액션 아이템, 웨이브 계획 초안, Kickoff 자료 초안.

### P3 수행·통제 (Execute & Control)
- 목적: 계획대로 수행하고 범위·일정·리스크를 통제한다.
- 활동: 작업 단위 계획(작업 내용, 온라인/오프라인 여부·소요시간, 고객 사전 준비, 작업 후 정상 확인 방안) → 수행 → 확인을 반복. Pilot 1건으로 절차를 검증한 뒤 웨이브를 확장. 주간·월간 현황 보고, 정기 검토회의, 변경 요청 관리, Key Milestone 고객 리뷰, Workbook 기반 수행(체크 이벤트 3).
- 산출물: 작업계획서, 웨이브별 이관 결과서, 성능 분석 보고서, 주간 Status Report, Change Request, 갱신된 리스크·이슈 대장.
- 게이트 G3: 각 Key Milestone 고객 리뷰 완료.
- AI 자동화 후보(핵심): 주간 업데이트 입력 → Workbook 자동 갱신 → 주간 보고서·RAG 상태·OKR 진척 자동 생성, 리스크 조기 경보.

### P4 인수·이관 (Acceptance & Transition)
- 목적: 고객이 결과를 확인하고 운영 조직이 넘겨받는다.
- 활동: 인수시험서 작성(인도 품목·요건 기준), 인수시험, 인수 조건 확인(요건 반영, 정상 가동, 이관 전후 성능 유지), 개별 인수 확인, 운영 절차·점검 절차·장애 연락망 정비, 운영자 교육과 기술 이전, 안정화 지원.
- 산출물: 인수시험서·결과, 인수 확인서, 운영 절차서, 교육 자료, 최종 구성 정보.
- 게이트 G4: 고객 인수 서명, 운영 이관 완료.
- AI 자동화 후보: 인도 품목·요건에서 인수시험 체크리스트 생성, 운영 절차서 초안.

### P5 종료 (Close)
- 목적: 공식 종료하고 교훈을 다음 프로젝트에 남긴다.
- 활동: 고객 협의 후 Closing 미팅·완료 보고(체크 이벤트 4), 고객 피드백 수집, Lessons Learned 리뷰, 운영 조직 공식 이관.
- 산출물: Closing 자료(완료 보고서), Feedback Form, Lessons Learned.
- 게이트 G5: 고객 협의 종료, 완료 보고 승인.
- AI 자동화 후보: 프로젝트 전체 Workbook·보고서에서 완료 보고서·Lessons Learned 초안 생성.

## 3. 공통 거버넌스

| 항목 | 기준 |
|---|---|
| 단일 기준 데이터 | Project Workbook (Actions, Risks, Issues, Changes, Assumptions, WBS, Requirements & Quality) |
| 보고 주기 | 주간 Status Report, 월간 진척 보고, 정기 검토회의(최소 2주 단위) |
| 변경 관리 | 범위·일정·비용·자원 변경은 Change Request로 기록·승인 |
| 품질 점검 | Quality Health Check: 4대 체크 이벤트(Handover, 합의 후 Kickoff, Workbook 기반 수행, 고객 협의 종료) + 정기 점검 + 무작위 감사 |
| 인수 규칙 | 인도품목 고객 검토 기한, 반려 시 보완 사항 명시, 개별 인수 확인 기록 |
| 진척 측정 | 단계별 가중치(예: 준비 3% · 분석 15% · 설계 20% · 구축·이관 57% · 안정화 5%) + 공동 OKR 핵심 결과 |

## 4. 포트폴리오 자동화 범위 제안 (5일)

- 실제 동작 1순위: P3 주간 루프 — 업데이트 입력 → Workbook 갱신 → 주간 보고서·리스크 경보·OKR 진척 생성 → PM 승인 후 확정.
- 실제 동작 2순위: P0→P1 — SOW에서 범위·리스크 추출 → Handover 체크리스트·Charter·OKR 초안.
- 설계로만 제시: P2 웨이브 계획, P4 인수 체크리스트, P5 완료 보고 자동화.
- 시연 데이터: 가상 고객의 레거시 DW → Databricks 마이그레이션 engagement.
